# 🔀 Тумблер

**Пускай через VPN только нужные приложения: остальной трафик идёт напрямую.**

Windows (WPF) · Linux (Avalonia) · .NET 10

</div>

---

## Зачем это нужно

Обычный VPN-клиент отправляет в туннель либо весь компьютер (режим TUN), либо только то, что умеет работать
с системным прокси. Чаще всего хочется другого: Discord, Telegram и браузер пусть идут через VPN, а игры,
торренты и банковские приложения работают напрямую, без лишнего пинга и блокировок.

**Тумблер** делает это одним переключателем у каждого приложения. Свой VPN он не поднимает. Он перехватывает
трафик выбранных программ и отправляет его в уже запущенный VPN-клиент через локальный порт SOCKS5.

```
  Discord ──┐
  Telegram ─┼──▶ Тумблер ──▶ SOCKS5 VPN-клиента (127.0.0.1:порт) ──▶ VPN-сервер ──▶ интернет
  Chrome ───┘
  Игры, Steam, всё остальное ─────────────────────────────────────────────────────▶ интернет напрямую
```

## Возможности

### 🎛 Управление
- **Список запущенных приложений с переключателями.** Включил тумблер, и приложение пошло через VPN.
- **Отдельный порт для каждого приложения**: одно можно пустить через «всё через VPN», другое через «по правилам».
- **Профили.** Именованные наборы тумблеров («Работа», «Игры»…), между ними можно быстро переключаться.
- **Пауза одной кнопкой**: всё временно идёт напрямую.
- **Глобальная горячая клавиша** (например, `Ctrl+Alt+P`) срабатывает, даже когда окно свёрнуто в трей.
- **Значок в трее** меняет цвет по состоянию, в его меню есть пауза и профили.
- **Перезапуск соединений приложения** (⟳): у уже открытой программы через VPN пойдут и новые соединения.
- **Иконки закрытых приложений**: выбранные программы остаются в списке, даже когда они не запущены.

### 🔍 Умная настройка
- **Автопоиск портов прокси**: находит запущенные VPN-клиенты и их локальные порты SOCKS5.
- **Интеграция с Karing**: читает его настройки, предлагает порты «всё через VPN» и «по правилам»
  и показывает, сколько соединений сейчас идёт через прокси и через какой сервер.
- **Предупреждение о TUN**: если в клиенте включён режим TUN, Тумблер об этом скажет, ведь тогда
  в VPN уходит весь компьютер.
- **Поведение при падении VPN** на выбор: выбранные приложения остаются без сети (kill switch)
  или временно идут напрямую.

### 🩺 Диагностика
Проверяет всю цепочку **приложение → перехватчик → прокси → интернет** и говорит, какое звено сломано:
- служба и драйвер установлены и запущены;
- порт отвечает по SOCKS5;
- прокси поддерживает UDP (`UDP ASSOCIATE`), без этого не работает голос в Discord;
- через прокси реально открывается интернет (с замером времени ответа);
- брандмауэр Windows не блокирует перехватчик.

Отчёт можно скопировать или сохранить в файл.

### 📖 Встроенная справка
Пошаговые инструкции для популярных клиентов. Раздел про запущенный клиент открывается автоматически:

| Клиент | Порт по умолчанию |
|---|---|
| Karing | 3066 / 3067 (читается из настроек) |
| v2rayN | 10808 |
| NekoBox / nekoray / Throne | 2080 |
| Hiddify | 12334 |
| Clash Verge Rev / FlClash / Mihomo | 7897 / 7890 |

### ⚙️ Установка без возни
Мастер первого запуска сам ставит всё нужное:
- драйвер **Windows Packet Filter**;
- службу **ProxiFyre**;
- **Microsoft Visual C++ Runtime** (скачивается с `aka.ms` и запускается только после проверки подписи Microsoft);
- правило брандмауэра.

Установщики драйвера и ProxiFyre встроены в exe без изменений. Перед установкой Тумблер сверяет их
**SHA-256** с зашитыми в код значениями. Удаление тоже в один клик из настроек.

Автозапуск с Windows сделан через задачу планировщика с наивысшими правами, поэтому при входе
в систему не появляется окно UAC.

## Как это устроено

### Windows
```
Тумблер (WPF, права администратора)
  ├── пишет app-config.json ──▶ служба ProxiFyre ──▶ драйвер Windows Packet Filter (NDIS)
  │                               перехватывает TCP/UDP выбранных exe и заворачивает их в SOCKS5
  ├── Scanner: процессы, TCP-соединения, слушающие порты, TUN-адаптеры
  ├── Diagnostics + собственный минимальный SOCKS5-клиент для проверок
  └── Tray, Hotkey, Autostart (schtasks), Setup (msiexec, icacls, netsh)
```

Сам перехват трафика выполняет [ProxiFyre](https://github.com/wiresock/proxifyre) на драйвере
[Windows Packet Filter](https://www.ntkernel.com/windows-packet-filter/). Тумблер служит для них удобной
оболочкой: управляет конфигом и службой, находит порты, следит за состоянием и диагностирует проблемы.

### Linux
Отдельная реализация с тем же интерфейсом, но на нативных механизмах ядра:
```
GUI (Avalonia) ──Unix-сокет /run/tumbler/tumbler.sock──▶ служба tumbler (systemd, root)
                                                           ├── cgroup v2 для процессов выбранных приложений
                                                           ├── правила nftables + policy routing
                                                           └── hev-socks5-tunnel: TUN → SOCKS5 по каждому порту
```
Служба раз в секунду приводит систему к нужному состоянию. Все шаги идемпотентны: если один сбоит,
он чинится на следующем круге. Доступ к сокету проверяется по `SO_PEERCRED`.

Управление из терминала:
```bash
tumbler status    # что работает
tumbler pause     # всё напрямую
tumbler resume    # снова через VPN
tumbler toggle    # переключить (удобно повесить на горячую клавишу)
```

> Linux-версия пока не проверена на реальной системе. Требования: x86_64, ядро 5.13+, systemd,
> nftables, iproute2 (Ubuntu 22.04+, Debian 12+, Fedora 36+, Arch, openSUSE Tumbleweed).

## Сборка

Нужен [.NET 10 SDK](https://dotnet.microsoft.com/download).

```bash
# Windows: один самодостаточный exe
dotnet publish Tumbler.csproj -c Release -r win-x64 --self-contained -p:PublishSingleFile=true -o dist

# Linux
dotnet publish Linux/Tumbler.Linux.csproj -c Release -r linux-x64 --self-contained -p:PublishSingleFile=true -o Linux/publish-linux
```

### Ключи командной строки (Windows)
| Ключ | Что делает |
|---|---|
| `--tray` | запуститься свёрнутым в трей |
| `--profile ИМЯ` | переключиться на профиль (создать, если его нет) |
| `--toggle имя.exe` | переключить тумблер приложения |
| `--route имя.exe=порт` | назначить приложению свой порт |
| `--fallback direct\|block` | что делать, когда VPN недоступен |
| `--diag файл` | записать отчёт диагностики |
| `--selftest файл` | проверить встроенные установщики, подписи и поиск прокси |

## Структура

```
├── *.cs, *.xaml          Windows-версия (WPF)
├── Shared/               общий код: настройки, SOCKS5-клиент, тексты
├── Payload/              официальные установщики WinPacketFilter и ProxiFyre (встраиваются в exe)
└── Linux/
    ├── Gui/              интерфейс на Avalonia
    ├── Daemon/           служба: cgroup, nftables, маршруты, туннели
    └── Payload/          hev-socks5-tunnel
```
